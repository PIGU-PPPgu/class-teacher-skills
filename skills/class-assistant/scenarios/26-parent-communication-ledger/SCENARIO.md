     1|# 场景 26｜家校沟通台账
     2|
     3|## 场景目标
     4|把与家长的沟通记录整理成可持续维护、可回溯、便于后续跟进的结构化台账。
     5|
     6|## 适用时机
     7|- 需要持续记录和家长的沟通情况
     8|- 需要区分已沟通事项、待跟进事项和结果反馈
     9|- 需要为月度复盘、敏感事项留痕或内部交接做准备
    10|- 需要避免“沟通过但找不到记录”
    11|- 不适合替代学校正式系统中的法定留档
    12|
    13|## 输入
    14|- 必填信息：日期、学生姓名或编号、沟通对象、沟通事由、沟通结果
    15|- 可选信息：沟通方式、家长反馈、老师判断、后续动作、下次跟进时间
    16|- 缺失时默认：按“时间—对象—事由—结果—后续动作”输出
    17|
    18|## 输出
    19|- 默认输出：一版家校沟通台账
    20|- 可选输出：单个学生沟通汇总、待跟进清单、月度沟通复盘版
    21|- 输出对象：班主任、内部协作老师、个人留档
    22|
    23|## 推荐语气
    24|- 客观
    25|- 简洁
    26|- 留痕导向
    27|- 可执行
    28|- 不情绪化
    29|
    30|## 文件说明
    31|- `templates.md`：台账模板与单次记录模板
    32|- `examples/`：脱敏输入输出样例
    33|- `scripts/`：如后续需要可接 CSV/JSON 维护脚本
    34|
    35|## 直接给 AI 的说法
    36|- 请把下面几次家校沟通整理成一份台账。
    37|- 请根据这些零散记录，生成一版待跟进的家校沟通表。
    38|- 请把这名学生最近三次和家长的沟通整理成汇总。
    39|
    40|## 注意事项
    41|- 默认用于内部，不直接转发给家长
    42|- 只记录已发生事实，不补写主观推断
    43|- 涉及敏感家庭情况时，控制细节披露范围
    44|

## 风格要求
输出风格严格遵循 `skills/VOICE_ANCHOR.md`。禁止使用套话式鼓励、万能结尾、空泛形容词。
